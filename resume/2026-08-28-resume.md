## 8/28/2026 — providers.csv repair + expansion (UNCOMMITTED, local only)

Went live and started community outreach; found Vision Professionals had 2 of 14 doctors
and 1 of 5 offices in the directory. Investigating that turned up two real data bugs.

### Bug 1: column shift (fixed)
The header had 17 columns (`…,phone,email,website,specialty,…`) but 44 of the 45 rows were
still in the old 15-column layout, padded rather than migrated. The site reads by header
NAME, so every provider card below the phone number showed the wrong field — `email` showed
the specialty, `catComanage` showed a distance, `doctors` showed `false`, etc. Only row 45
(the test row, created through the admin UI) was correct.

**Why it stayed broken:** the admin UI round-trips values into the same wrong positions, so
editing a provider preserved the shift instead of fixing it.

**Worse:** the 8/25 edit to Travis, Beth A. hit dropdown fields (`specialty`, `ownership`,
`catComanage`, `glaucTC`) whose shifted values didn't match any valid option, so they fell
back to defaults and **destroyed that row's distMain/distEast**. Recovered from git
(commit `929507b`). The repair was rebuilt from that pre-edit commit; the test string
"TEST 8/25/2026" added in that edit was dropped.

### Bug 2: lossy encoding (fixed)
The file was pure ASCII with 40 literal `?` characters where `—` and `★` used to be —
e.g. `Eye Designs ? New Albany`, `Rated 4.9 ? (417 reviews)`. Restored. The commit path in
`index.html` uses `TextEncoder` and is UTF-8-safe, so this was almost certainly caused by an
external tool, not the site. **If the `?` come back after an admin edit, the site is the
culprit and needs looking at.**

## Open follow-ups (unchanged)
1. **Forgot-password flow.** Paused mid-decision on 8/28. Constraint found: any reset must
   write `users.json`, which needs the PAT, so the reset can only be completed on a browser
   that already has a token. Options were (a) admin-issued temp password with a forced change
   at next sign-in [recommended], (b) one-time reset links via a new `resets.json` holding
   only SHA-256 hashes, (c) both, (d) login-screen wording only.
   **Also found:** `init()` fires `loadUsersFromGitHub()` without awaiting it (`index.html:2244`)
   while `attemptLogin()` verifies against the localStorage cache (`index.html:1840`) — so a
   password changed on one device can be rejected on another until the cache refreshes.
   Fix: on failed verify, re-fetch `users.json` and retry once.
2. **[BUG — iPad] Token paste doesn't stick on iPad.** Undiagnosed. Suspects: Private
   Browsing blocking localStorage, clipboard whitespace, touch event handling, ITP purging.
3. **Eliminate per-computer PAT paste.** Serverless proxy (Cloudflare Workers / Vercel),
   ~2-4 hrs. Makes #2 irrelevant.
4. **Remove USERS_DEFAULT plaintext** as a hardening pass.
